# ClipSync 前端

基于 Vue 3 + Vite 构建的跨设备剪贴板与文件同步前端应用。

## 技术栈

- **Vue 3**：组合式 API
- **Vite 8**：构建工具（要求 Node.js 20.19+ 或 22.12+）
- **Pinia**：状态管理
- **Vue Router**：路由管理
- **Axios**：HTTP 客户端
- **WebSocket**：实时通信
- **@lucide/vue**：图标
- **@fontsource-variable/inter**：Inter 字体（随前端打包）

## 开发

### 安装依赖

```bash
npm install
```

### 启动开发服务器

```bash
npm run dev
```

访问 http://localhost:3000

### 构建生产版本

```bash
npm run build
```

构建产物在 `dist/` 目录。`npm run preview` 在本机预览构建产物（端口 4173，沿用开发服务器的 `/api`、`/ws` 代理，需要后端在运行）。

### 测试与验证

前端没有自动化测试。改动前端代码（`src/`、依赖、`vite.config.js`）后运行 `npm run build` 确认能构建，界面行为在浏览器里手动验证，待验证项见 [TODO.md](../TODO.md)。只改文档不需要构建。

## 功能模块

### 认证 (Login/Register)
- 用户登录/注册；注册时用户名和邀请码自动去掉首尾空格（密码不处理）；注册页地址带 `?code=` 时自动填好邀请码（邀请信息里的注册链接），仍可修改
- 登录后回到原来的页面：未登录访问受保护页面、或登录过期被踢出时，登录页地址带 `?redirect=<原页面>`，登录成功后跳回；只接受站内路径（以单个 `/` 开头），其余以及指向登录页、注册页、快速访问页的都回到 `/clipboard`
- 登录页下方有「快速访问码」输入框：输入 `用户名@访问码` 换取快速访问凭证后进入 `/quick`（见下方「快速访问」）
- JWT Token 管理
- 路由守卫

### 云剪切板 (Clipboard)
- 实时文本同步（本地有未保存编辑时，远端更新不覆盖编辑框，只提示「已在别处更新」；没有未保存编辑，或服务端内容与编辑框一致时，编辑所基于的版本号跟着更新，保存不会被误报冲突）
- 首次加载失败时不显示空编辑框，显示「加载失败」和「重试」，保存按钮禁用，避免把没加载出来的内容当成空剪切板去覆盖
- 保存相同内容后端不加版本号，别的设备随后保存不会被误报冲突
- Ctrl/⌘ + S 或「保存」按钮保存（提示文字按设备显示 ⌘ + S 或 Ctrl + S）
- 保存带上编辑开始时的版本号；内容已在别处改过（409）时弹窗选择「载入最新内容」「仍然覆盖」或「继续编辑」
- 页头的访问码按钮：设置、修改或清除云剪切板的访问码
- 有未保存的修改时，切换页面、退出登录会先弹对话框确认；刷新或关闭标签页由浏览器自带的确认框拦截
- 历史记录：查看、载入编辑框、恢复为当前文本、删除；编辑框里有未保存的修改时点「恢复」，确认框改成危险提示（修改会丢失，也不会进入历史），恢复和「载入最新内容」期间不弹「已在别处更新」
- 页面正好占满窗口高度：编辑框填满页头以下的空间（不可手动拖动大小），底部状态栏（已保存 / 字符数）始终可见；历史面板与编辑框等高，条目多时在面板内滚动，窗口宽度 1024px 以下排到编辑框下方。窗口太矮时（低于约 480px）改为整页滚动
- WebSocket 推送

### 文本栏目 (Texts)
- 多段独立文本，每段有可选标题（最多 100 字）和编辑框，单独保存（Ctrl/⌘ + S 或「保存」按钮）；每人最多 200 段，到上限时禁用「新建」
- 列表里超过 64KB 的文本只显示开头，点「载入全文后编辑」再取全文
- 每段旁有访问码按钮；删除时访问码随之消失
- 编辑草稿由 `utils/textDrafts.js` 管理：其他终端或快速访问页改了某段，没有未保存修改的直接更新，有未保存修改的只标记「已在别处更新」；长文本展开时请求全文期间用户已开始编辑的同样只标记；保存期间别处又改过的，保存响应不覆盖列表，也标记「已在别处更新」；保存冲突处理与云剪切板相同
- 有未保存的修改时，切换页面、退出登录会先确认；刷新或关闭标签页由浏览器确认

### 文件管理 (Files)
- 分片上传（请求 1MB/片，实际以服务端返回的分片大小为准），同一时间只允许一个上传；中途失败自动取消会话、释放配额；上传中点「退出登录」时确认框提示会取消上传，确认后先取消进行中的会话（此时登录凭证还在）再登出
- 上传中刷新或关闭标签页：先由浏览器确认；确认离开后用 `keepalive` 请求尽力取消会话（释放配额）。已进入「完成上传」阶段的不取消，避免服务端正在合并时丢文件。取消请求没发出去时，会话在 `UPLOAD_SESSION_TTL_HOURS`（默认 24 小时）后过期
- 「完成上传」请求的超时为 600 秒（服务端要合并分片，大文件可能超过默认的 30 秒）；完成后刷新列表失败不算上传失败，列表由随后的 `file_added` 推送补上
- 上传进度显示
- 文件列表与下载：列表加载失败时页面显示原因和「重试」按钮，不显示成「还没有文件」；下载按钮在下载期间禁用并显示百分比（下载需带登录凭证，浏览器收完整个文件才弹出保存）
- 配额显示（已用 + 上传中）
- 每个文件旁有访问码按钮；删除文件时访问码随之消失

### 访问码设置弹窗 (AccessCodeDialog)
- 访问码 4–32 位字母、数字与 `_ - .`，不区分大小写（输入后转小写），前后端规则一致（`utils/accessCode.js`）
- 实时显示要在登录页输入的完整访问码 `用户名@访问码`
- 有效期：常用选项或自填小时数（0 为永久，最长 8760 小时）；修改已有访问码且原有效期还没到时，默认「保持不变」，不会顺带改掉原有效期；原访问码已过期或永久有效时，默认 0 小时（永久）
- 已设置时可「清除访问码」（先确认）；按 Esc 关闭

### 访问码总览 (AccessCodes)
- 按访问码分组列出设置过访问码的内容，每组显示完整访问码（可复制）和其中的云剪切板 / 文本 / 文件；可逐项清除
- 是否过期由页面按全站共用的时钟（`utils/accessCode.js` 的 `clock`）计算，页面开着时每 30 秒重算；云剪切板、文本、文件页条目旁的访问码按钮读同一个时钟，到期后自己变成「已过期」
- 列表加载失败时显示原因和「重试」按钮；访问码改动、文本或文件被删除、重连触发的刷新是静默的

### 快速访问 (QuickAccess)
- 凭快速访问凭证进入（不需要登录）；凭证存在 sessionStorage，刷新页面仍在，关掉标签页即失效，2 小时后到期；与登录 token 互不影响
- 列出该访问码下的云剪切板、文本、文件：文本可查看与修改（含标题，冲突处理同上）、可复制，文件可下载（以 blob 方式带凭证下载，显示进度）；没有新建、删除、上传、修改访问码的入口
- 实时刷新：用单独的 WebSocket 实例 `quickWs`，收到 `access_items_changed` 静默重拉；连接（重新）建立时补拉
- 访问码失效（被清除、修改、过期、属主被禁用、凭证到期）：接口返回 401 或连接被 1008 断开时，页面顶部提示，禁止保存与下载，未保存的内容仍留在页面上可以复制；点「重新输入」回登录页
- 访问码有效时点「退出」先弹对话框确认，有未保存的修改时提示会丢失修改；访问码失效后点「重新输入」直接回登录页。浏览器后退等离开方式只在有未保存的修改时确认

### 退出登录 (Home)
- 点侧栏底部的「退出登录」一律先弹对话框确认，防止误点；云剪切板或文本页有未保存的文字、或有文件正在上传时，对话框换成危险提示（修改会丢失 / 上传会被取消），默认聚焦「继续编辑」或「继续上传」
- 退出时先取消进行中的上传会话，再清空各 store；已清空的页面不会因为 store 被重置而弹「已在别处更新」「已在别处删除」之类的误报

### 侧栏 GitHub 链接 (Home)
- 侧栏最底部、账号行下面有一行灰色小字「开源项目 · GitHub」，新标签页打开项目主页；窄屏下在抽屉菜单里
- 是否显示由后台系统设置的 `show_github_link` 决定（默认显示），值随 `/auth/me` 下发，存在 user store 的 `showGithubLink` getter 里；用户刷新页面或重新登录后生效
- 链接地址写在 `Home.vue` 的 `REPO_URL`，不可配置；GitHub 标志是内联 SVG（lucide 不含品牌图标）

### 管理后台 (Admin)
- 「概览」tab：用户总数、活跃用户、文件总数、总存储、访问码总数、有效访问码六张统计卡（admin 及以上）
- 用户列表，分页（admin 及以上可看）；每行按钮按权限显示（与后端校验一致，规则见 README 第 4 节）：
  - admin：只在普通用户行看到改配额、启用 / 禁用
  - 超管：所有行可改配额；普通用户与管理员行另有启用 / 禁用、设为管理员 / 取消管理员（先确认）、删除；除自己以外的行有「查看文本内容」
  - 「查看文本内容」打开只读弹窗 `UserContentDialog.vue`：云剪切板当前文本、剪切板历史、文本栏目三个分组，列表里超过 64KB 的条目点开时再取全文；没有修改、删除、恢复的入口
- 邀请码管理（admin 及以上；码的状态分「已使用」「已过期」「可用」）
  - 创建弹窗填数量（1–20）、有效天数和选填备注（最多 100 字）；有效期输入框下有快捷按钮 7 天、14 天、30 天、90 天、半年（180 天）、一年（365 天）、永久，点一下填入天数，当前天数与某个按钮一致时该按钮高亮，输入框仍可手动填其他天数；生成后同一弹窗切换为「生成结果」页，只列本次生成的码：每行可单独复制；「复制邀请码」只复制码（每行一个），「复制邀请信息」复制带标题、有效期和注册链接的整段文字（格式见 README 第 9 节「邀请信息」）；点「完成」关闭，这批已在列表里
  - 列表按批次显示（每次生成是一批，1 个也算），默认收起：备注（没有时显示「无备注」）、生成时间、生成人、个数、有效期概要（只看未使用的码，不一致时显示「各不相同」）、可用 / 已过期 / 已使用各几个；只有 1 个码的批次在标题行直接显示码
  - 每批的操作：「复制邀请信息」只放这批里可用的码（没有可用的码时按钮不可用）；改备注（留空为清除）；删除这批里所有未使用的码（已使用的保留，这批记录和备注也保留）
  - 点开批次看其中每个码：复制、修改有效期（填天数，从现在算，0 为永久）、删除；勾选多行后工具栏出现「修改有效期」批量修改，可以跨批次勾选；每批表头的勾选框只全选这一批；列表刷新后已不可选的勾选自动去掉；可用的码多于 1 个时底部有「只复制可用的邀请码」
  - 搜索框匹配备注、生成人和邀请码（邀请码不分大小写、可不带短横线）；按邀请码搜到的批次自动展开并高亮那个码。状态筛选按批次判断：全部 / 有可用的 / 有已过期的 / 已用完，按钮上的数字是当前搜索结果里各有几批。搜索和筛选都在前端完成，不请求后端
  - 已使用的码不显示勾选框、修改有效期和删除按钮（后端返回 409）；使用者账号被删除后显示「已删除的用户」
- 文件元数据查看，分页（admin 及以上）；超管每行有下载按钮，与文件页共用 `filesStore.downloadFile`（带进度，下载中按钮不可用），admin 没有下载按钮
- 系统设置（开放注册、显示 GitHub 链接、新用户默认配额，配额为空或非整数时拒绝保存；admin 与超管都可保存；保存后重取一次 `/auth/me`，本页侧栏的 GitHub 链接立即跟着开关变化）；设置没加载成功时表单显示的是默认值而不是真实设置，此时提示并禁用保存，避免覆盖真实设置
- 「系统信息」tab（admin 及以上）：版本（为空显示「开发版本」）、提交号、分支、构建时间、部署时间、本次启动时间、已运行时长（取到数据后在页面上每 30 秒累加一次，不重新请求）；下方部署记录表，当前运行的那条标「当前」；超管每行有改备注按钮（最多 200 字，留空为清除），admin 只能看

## 环境配置

### 开发环境

Vite 开发服务器会将 `/api` 和 `/ws` 请求代理到后端（`http://127.0.0.1:8000`）。

配置位于 `vite.config.js`：

```js
server: {
  port: 3000,
  proxy: {
    '/api': {
      // 用 127.0.0.1：后端只监听 IPv4，localhost 可能先解析成 ::1 导致代理失败
      target: 'http://127.0.0.1:8000',
      // 保留浏览器的 Host（localhost:3000），与经 Nginx 部署时后端看到的 Host 一致
      changeOrigin: false,
    },
    '/ws': {
      target: 'ws://127.0.0.1:8000',
      ws: true,
    },
  },
}
```

### 生产环境

生产环境由 frontend 容器（[Dockerfile.frontend](../deployment/docker/Dockerfile.frontend)）在镜像内执行 `npm ci && npm run build`，产物 `dist/` 由容器里的 Nginx 托管，并反代 `/api`、`/ws` 到 backend 容器。Nginx 规则以 [deployment/docker/nginx-common.conf](../deployment/docker/nginx-common.conf) 为准（HTTP 站点 `nginx-docker.conf`、HTTPS 站点 `nginx-https.conf` 都引用它），部署步骤见 [deployment/DEPLOYMENT.md](../deployment/DEPLOYMENT.md)。

> 自己写反代时必须设置 `X-Forwarded-For`，否则后端只能看到 127.0.0.1，所有用户会共用一个限流额度。

## API 请求流程

1. **请求拦截**：自动附加 JWT Token（读本标签页 user store 里的 token，不读 localStorage，避免多标签页串号）
2. **发起请求**：通过 Axios 发送到后端
3. **响应拦截**：
   - 401，或带响应头 `X-Auth-Error: disabled` 的 403（账号被禁用）：登出并跳转登录页。登录 / 注册接口本身的 401、403 不触发；当前在登录页、注册页或快速访问页时只登出、不跳转
   - 普通 403（权限不足）与其他错误：提取错误文字返回（`api/request.js` 的 `extractMessage`）：
     - 取 `detail`（后端的错误含限流的 429 都用这个字段）
     - 422 校验错误的 `detail` 是数组，取各条 `msg` 并去掉 pydantic 自带的英文前缀 `Value error,`
     - 429 没有 `detail` 时提示「操作过于频繁，请稍后再试」；413 没有文字时提示「文件或请求过大」；都没有时为「请求失败」
     - 下载等 `responseType: 'blob'` 的请求，错误响应体先按 JSON 解析再提取

快速访问的请求走 `quickRequest.js`：带快速访问凭证，401 只结束快速访问（`useQuickStore().handleLost()`），不影响登录状态。

其他标签页登录、登出或换账号会改写 localStorage 中的 token，本页监听 `storage` 事件后整页重载。启动时只有 401 / 403 才清掉 token，网络错误或 5xx 保留登录状态并在登录页提示「暂时无法连接服务器」。

## WebSocket 连接

- **URL 构建**：根据当前协议（http/https）自动选择 `ws://` 或 `wss://`
- **认证**：Token 通过子协议传递（`new WebSocket(url, ['clipsync.v1', 'bearer.<token>'])`），不放 URL，避免被 access log 记录
- **心跳**：每 30 秒发送一次 ping；发出后 10 秒内没收到任何消息，就认为连接已半断（休眠、切网络后浏览器可能还没察觉）并立即重建
- **重连**：指数退避（1s、2s、4s…，最长 30s），不限次数；网络恢复或页面回到前台时立即重试：已断开的直接重连，看起来仍连着的先发一次 ping 探测，没有回应就重建；重连只用本标签页内存里的 token
- **关闭码**：已连接后被踢下线（账号被禁用或删除）为 1008，停止重连并登出；握手被拒时浏览器只能看到 1006，此时调一次 `/api/auth/me` 确认会话，401 / 禁用 403 则登出、不再重连，其他情况继续重连
- **补拉**：各页面同时订阅 `open`，连接（重新）建立后重拉一次数据，断线期间的变更不会漏掉
- **广播范围**：后端发给该用户的全部连接，触发变更的终端自己也会收到
- **离线发送**：连接未打开时 `send` 直接返回 false，不排队（客户端只发心跳，积压没有意义）
- **快速访问页**：`utils/websocket.js` 导出 `WebSocketManager` 类，快速访问页另建实例 `quickWs`（`stores/quick.js`），用快速访问凭证连接，重连与心跳规则相同；1008 时提示访问码已失效，握手被拒时请求一次 `/api/access/items` 确认

## 状态管理

所有状态通过 Pinia stores 管理，主要包括：

- **用户状态**：token、用户信息、登录状态、配额（已用 + 上传中）、启动时的连接错误提示
- **云剪切板状态**：当前文本、版本号、访问码与过期时间、历史记录、历史面板是否打开、编辑框是否有未保存的修改
- **文本栏目状态**：文本列表（长文本只有开头）、每人上限、列表加载失败的原因、是否有未保存的修改
- **文件状态**：文件列表（含访问码）、列表加载失败的原因、上传进度、是否正在上传、各文件的下载进度
- **访问码状态**：按访问码分组的总览（后端原始数据）、用户名、加载失败的原因
- **快速访问状态**：快速访问凭证、属主用户名、访问码、到期时间、是否已失效（不随登出重置，与登录状态互不影响）
- **管理后台状态**：统计数据、用户列表与分页、邀请码批次列表（每批带其中全部邀请码）、文件元数据列表与分页、系统设置、系统信息（含取到数据的本机时间）

登出时会清理各 store 的 WebSocket 监听并重置状态，下一个登录的账号看不到上一个账号的数据。

## 路由守卫

- **页面文件加载失败**：各页面按需加载。服务器升级后，已打开的旧页面里记的文件名在服务器上已不存在，点菜单会加载失败；`router.onError` 遇到这类错误（含页面样式文件预加载失败的 `Unable to preload CSS`）会整页刷新一次拿到新版本，10 秒内已刷新过则不再刷（这种情况不更新刷新时间），避免服务器真的连不上时陷入刷新循环
- **未登录**：自动跳转到 `/login`
- **已登录访问登录页或注册页**：跳转到 `/clipboard`
- **不存在的路径**：重定向到 `/clipboard`（未登录时再由守卫带到 `/login`）
- **快速访问页 `/quick`**：不需要登录；没有快速访问凭证时页面自己回到 `/login`
- **非管理员访问管理后台**：跳转到 `/clipboard`

## 样式规范

设计变量与共用组件样式都在 `src/style.css`。页面只引用变量（`var(--color-text)` 等）和共用类（`.btn`、`.input`、`.table`、`.modal`……），不写死颜色值；页面自己的 `<style scoped>` 只放该页特有的布局。

- **颜色**：浅色与深色两套主题，都以中性色为主（浅色白底、浅灰分层；深色近黑底、深灰分层）
  - 两套颜色变量都在 `style.css`：浅色写在 `:root`，深色写在 `:root[data-theme='dark']`，只覆盖颜色与阴影；新增颜色变量时两套都要写
  - 主题开关（`ThemeToggle.vue`）放在侧栏底部、登录 / 注册页右上角、快速访问页顶栏，三档：跟随系统 / 浅色 / 深色，默认跟随系统
  - 选择存在本浏览器的 `localStorage`（键 `theme`，跟随系统时不存），不随账号同步；其他标签页切换后本页同步，跟随系统时系统深浅色变化立即生效（`utils/theme.js`）
  - `index.html` 里有一段同样规则的内联脚本，在页面渲染前设好 `data-theme`，深色用户刷新时不会先闪一下白底
  - 切换主题时颜色渐变约 0.35 秒：`utils/theme.js` 在切换那一刻给 `<html>` 临时加 `theme-switching`，`style.css` 据此让背景、文字、边框、图标、阴影的颜色过渡，结束后去掉；首次进入页面不渐变，系统开了「减少动态效果」时直接切换
  - 主按钮用近黑色，深色主题下用近白色（`--color-primary`）；强调色靛蓝（`--color-accent`）只用于链接、焦点框、进度条、开关
  - 状态色：成功 / 警示 / 危险各有正文色与浅底色（`--color-success`、`--color-success-subtle` 等）
  - 文字与状态色在各自主题的底色上满足 4.5:1 对比度
- **字体**：Inter（`@fontsource-variable/inter` 随前端打包，内网部署也能用，只含拉丁字符）；中文回落到系统字体（苹方、微软雅黑等）；代码与访问码用等宽字体（`.mono`）
- **字号**：12 / 13 / 14（正文）/ 15 / 17 / 20 / 24（页面标题）/ 32 / 40px
- **间距**：以 4px 为单位（`--space-1` 至 `--space-16`）
- **圆角**：6 / 8 / 12px；**阴影**：很轻的 `--shadow-xs` / `--shadow-sm`，悬停抬起的卡片用 `--shadow-md`，弹窗用 `--shadow-lg`
- **质感（玻璃）**：只改透明度、模糊、光泽与边缘，不改布局；颜色保持强调色靛蓝一个色系
  - 三套参数：
    | 场景 | 背景光斑 | 玻璃底色不透明度 | 光泽与亮边 | 卡片、表格、侧栏 | 折射幅度 |
    |------|------|------|------|------|------|
    | 浅色，登录 / 注册页 | 四角 + 中部，边缘收紧到 50% | 0.4 | 加倍 | 模糊 24px + 折射 | 50 |
    | 浅色，登录后的页面与快速访问页 | 无（纯白底） | 0.4 | 加倍 | 模糊 24px + 折射 | 50 |
    | 深色，所有页面 | 四角 + 中部，边缘 70% | 0.62 | 正常 | 只折射、不模糊 | 16 |
  - 背景光斑：同色系（靛蓝及相邻的蓝、紫蓝）的光斑铺在 `body::before`（变量 `--page-glow`），尺寸随窗口缩放，缓慢漂移（一圈 40 秒，只动 `transform`）。浅色登录 / 注册页由 `style.css` 的 `:root:not([data-theme='dark']):has(.auth)` 换上光斑（`.auth` 是 `AuthLayout.vue` 的外层），不支持 `:has()` 的浏览器在登录页也是纯白底；`Home.vue` 与 `AuthLayout.vue` 的外层不设底色，让光斑透出来
  - 玻璃面：卡片、表格、侧栏、空状态、登录页左侧、快速访问页用半透明底色（`--color-glass` / `--color-glass-subtle`，与原底色同色、只降不透明度）；卡片、表格、侧栏、弹窗、次要按钮、当前菜单项、主题开关当前档表面有斜向光泽（`--glass-sheen`），边缘有上沿亮边、下沿暗边、内圈亮边（`--glass-shadow`），显出玻璃厚度。主按钮底色不变，表面一层淡光泽（`--btn-primary-sheen`）加上下两道边
  - 模糊：卡片、表格、侧栏读 `--surface-filter`（浅色模糊 24px，深色不模糊）；叠在内容上的元素用 `backdrop-filter` 模糊背后的页面：弹窗遮罩与窄屏抽屉遮罩（`--overlay-blur`）、提示条、窄屏顶栏、快速访问页顶栏（`--glass-blur`）；弹窗本身与窄屏抽屉侧栏叠在压暗的页面上，用接近不透明的底色，文字才清楚。提示条只在浏览器支持模糊时才变半透明，否则保持不透明
  - 液态折射：在 Chromium 内核浏览器（Chrome、Edge）上 `utils/glass.js` 给 `<html>` 加 `liquid-glass`，背后的内容经 `App.vue` 里的 SVG 滤镜按起伏纹理位移，像隔着有厚度的玻璃；浅色用 `#cs-liquid-light`（幅度 50），深色用 `#cs-liquid-dark`（幅度 16）。提示条、窄屏顶栏、快速访问页顶栏带 `.liquid`，改用 `--liquid-filter`（先轻度模糊再折射）；卡片、表格、侧栏的 `--surface-filter` 也加上折射。Safari、Firefox 只有普通毛玻璃
  - 悬停高光：有鼠标的设备上，主按钮、次要按钮、次要危险按钮、`.card-hover` 卡片悬停时表面有一团跟着鼠标走的柔光（`utils/glass.js` 写 `--mx` / `--my`，每帧最多更新一次）
  - 系统开启「降低透明度」时，玻璃一律换成不透明底色，不模糊、不折射，光斑去掉
  - 对比度按光斑最浓处核算：直接显示在背景上的弱提示文字（浅色 `#6b6b74`、深色 `#93939d`）、强调色与状态色都满足 4.5:1；调高光斑前要重新核算
- **加载中**：文本、文件、访问码、快速访问页的列表加载时显示骨架屏（`LoadingSkeleton.vue`，`variant="rows"` 是一张卡片里的多行，`variant="cards"` 是多张卡片），灰色占位块上有一道光扫过；屏幕阅读器读到「加载中…」
- **图标**：`@lucide/vue` 细线图标，`App.vue` 统一设默认 16px、线宽 1.75；不用 emoji
- **提示与确认**：不用浏览器原生 `alert` / `confirm` / `prompt`；操作结果用 `toast`（`utils/toast.js`），确认与输入用 `confirmDialog` / `promptDialog`，多选一（如保存冲突）用 `choiceDialog`（`utils/dialog.js`）；复制统一用 `copyText`（`utils/clipboard.js`）：成功弹提示，失败时用 `copyDialog` 显示内容让用户手动复制。危险操作的确认框默认聚焦「取消」
- **窄屏**：768px 以下侧栏收起为抽屉（顶栏菜单按钮打开），表格可横向滚动；900px 以下登录 / 注册页隐藏左侧品牌介绍
- **矮屏**：占满窗口高度的元素（侧栏、云剪切板页、对话框）用 `100dvh`（手机上不含地址栏），旧浏览器回落到 `100vh`；内容放不下时在元素内部滚动，不会被窗口底边裁掉
- **动效**：150ms 颜色过渡；背景光斑缓慢漂移；切换页面时内容从下方淡入（`.page`，不用 `.page` 的页面主体加 `.page-enter`）；按钮、侧栏菜单项按下时轻微缩小，松开时带一点回弹（`--ease-spring`）；弹窗弹出时带同样的回弹；带 `.card-hover` 的卡片（管理后台统计卡、访问码分组）在有鼠标的设备上悬停时抬起 2px、阴影加深。系统开启「减少动态效果」时关闭动画，光斑漂移、淡入、抬起、回弹都不生效，骨架屏只留静止的灰块

## 注意事项

1. **协议无关**：前端使用相对路径和动态协议选择，同时支持 HTTP 和 HTTPS
2. **Token 管理**：Token 存在 `localStorage`（刷新后恢复登录、跨标签页感知），请求与 WebSocket 使用本标签页 store 中的副本，分别经 `Authorization` header 与子协议传递
3. **文件上传**：采用分片上传（请求 1MB/片，以服务端返回为准），支持大文件
4. **WebSocket 事件**（只带信号，不含正文）：
   - `clipboard_updated`：保存（含快速访问修改）、恢复或删除历史后触发；云剪切板页静默重拉当前文本，历史面板打开时一并重拉历史
   - `texts_changed`：新建、保存（含快速访问修改）、删除文本后触发；文本页静默重拉列表，访问码页重拉总览
   - `file_added` / `file_deleted`：文件页静默重拉列表；访问码页在 `file_deleted` 时重拉总览；侧栏配额由 `Home.vue` 统一刷新（连接重新建立 `open` 时也刷新一次）
   - `access_codes_changed`：设置、修改、清除访问码，或删除带访问码的文本 / 文件后触发；访问码页重拉总览，云剪切板、文本、文件页重拉以显示最新访问码
   - `access_items_changed`：只发给快速访问页，访问码下的内容有变化时触发，快速访问页静默重拉
   - `quota_updated`：管理员或超管修改配额后触发，侧栏刷新配额
   - `role_updated`：超管修改本账号角色后触发，`Home.vue` 重取 `/auth/me`，侧栏的管理后台入口随之出现或消失；被取消管理员时正在后台页则转到云剪切板
5. **云剪切板历史**：列表里不超过 64KB 的条目带全文，更长的只有开头（`content` 为 null），点击时才按 id 取全文；点击条目把内容填入编辑框（不保存）；「恢复」按钮直接设为当前文本并同步；「删除」按钮删除该条历史
6. **权限控制**：前端隐藏只是体验层，后端必须做最终校验
