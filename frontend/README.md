# ClipSync 前端

基于 Vue 3 + Vite 构建的跨设备剪贴板与文件同步前端应用。

## 技术栈

- **Vue 3**：组合式 API
- **Vite 8**：构建工具（要求 Node.js 20.19+ 或 22.12+）
- **Pinia**：状态管理
- **Vue Router**：路由管理
- **Axios**：HTTP 客户端
- **WebSocket**：实时通信
- **@lucide/vue**：图标
- **@fontsource-variable/inter**：Inter 字体（随前端打包）

## 开发

### 安装依赖

```bash
npm install
```

### 启动开发服务器

```bash
npm run dev
```

访问 http://localhost:3000

### 构建生产版本

```bash
npm run build
```

构建产物在 `dist/` 目录。

### 测试与验证

前端没有自动化测试。改动前端代码（`src/`、依赖、`vite.config.js`）后运行 `npm run build` 确认能构建，界面行为在浏览器里手动验证，待验证项见 [TODO.md](../TODO.md)。只改文档不需要构建。

## 功能模块

### 认证 (Login/Register)
- 用户登录/注册；注册时用户名和邀请码自动去掉首尾空格（密码不处理）
- 登录后回到原来的页面：未登录访问受保护页面、或登录过期被踢出时，登录页地址带 `?redirect=<原页面>`，登录成功后跳回；只接受站内路径（以单个 `/` 开头），其余回到 `/clipboard`
- 登录页下方有「快速访问码」输入框：输入 `用户名@访问码` 换取快速访问凭证后进入 `/quick`（见下方「快速访问」）
- JWT Token 管理
- 路由守卫

### 云剪切板 (Clipboard)
- 实时文本同步（本地有未保存编辑时，远端更新不覆盖编辑框，只提示「已在别处更新」）
- 保存带上编辑开始时的版本号；内容已在别处改过（409）时弹窗选择「载入最新内容」「仍然覆盖」或「继续编辑」
- 页头的访问码按钮：设置、修改或清除云剪切板的访问码
- 有未保存的修改时，切换页面、退出登录会先弹对话框确认；刷新或关闭标签页由浏览器自带的确认框拦截
- 历史记录：查看、载入编辑框、恢复为当前文本、删除
- WebSocket 推送

### 文本栏目 (Texts)
- 多段独立文本，每段有可选标题（最多 100 字）和编辑框，单独保存（Ctrl/⌘ + S 或「保存」按钮）；每人最多 200 段，到上限时禁用「新建」
- 列表里超过 64KB 的文本只显示开头，点「载入全文后编辑」再取全文
- 每段旁有访问码按钮；删除时访问码随之消失
- 编辑草稿由 `utils/textDrafts.js` 管理：其他终端或快速访问页改了某段，没有未保存修改的直接更新，有未保存修改的只标记「已在别处更新」；保存冲突处理与云剪切板相同
- 有未保存的修改时，切换页面、退出登录会先确认；刷新或关闭标签页由浏览器确认

### 文件管理 (Files)
- 分片上传（1MB/片），同一时间只允许一个上传；中途失败自动取消会话、释放配额
- 上传中刷新或关闭标签页：先由浏览器确认；确认离开后用 `keepalive` 请求尽力取消会话（释放配额）。已进入「完成上传」阶段的不取消，避免服务端正在合并时丢文件。取消请求没发出去时，会话在 `UPLOAD_SESSION_TTL_HOURS`（默认 24 小时）后过期
- 「完成上传」请求的超时为 600 秒（服务端要合并分片，大文件可能超过默认的 30 秒）；完成后刷新列表失败不算上传失败，列表由随后的 `file_added` 推送补上
- 上传进度显示
- 文件列表与下载：列表加载失败时页面显示原因和「重试」按钮，不显示成「还没有文件」；下载按钮在下载期间禁用并显示百分比（下载需带登录凭证，浏览器收完整个文件才弹出保存）
- 配额显示（已用 + 上传中）
- 每个文件旁有访问码按钮；删除文件时访问码随之消失

### 访问码设置弹窗 (AccessCodeDialog)
- 访问码 4–32 位字母、数字与 `_ - .`，不区分大小写（输入后转小写），前后端规则一致（`utils/accessCode.js`）
- 实时显示要在登录页输入的完整访问码 `用户名@访问码`
- 有效期：常用选项或自填小时数（0 为永久，最长 8760 小时）；修改已有访问码时默认「保持不变」，不会顺带改掉原有效期
- 已设置时可「清除访问码」（先确认）；按 Esc 关闭

### 访问码总览 (AccessCodes)
- 按访问码分组列出设置过访问码的内容，每组显示完整访问码（可复制）和其中的云剪切板 / 文本 / 文件；可逐项清除
- 是否过期由页面按当前时间计算，页面开着时每 30 秒重算
- 列表加载失败时显示原因和「重试」按钮；访问码改动、文本或文件被删除、重连触发的刷新是静默的

### 快速访问 (QuickAccess)
- 凭快速访问凭证进入（不需要登录）；凭证存在 sessionStorage，刷新页面仍在，关掉标签页即失效，2 小时后到期；与登录 token 互不影响
- 列出该访问码下的云剪切板、文本、文件：文本可查看与修改（含标题，冲突处理同上）、可复制，文件可下载（以 blob 方式带凭证下载，显示进度）；没有新建、删除、上传、修改访问码的入口
- 实时刷新：用单独的 WebSocket 实例 `quickWs`，收到 `access_items_changed` 静默重拉；连接（重新）建立时补拉
- 访问码失效（被清除、修改、过期、属主被禁用、凭证到期）：接口返回 401 或连接被 1008 断开时，页面顶部提示，禁止保存与下载，未保存的内容仍留在页面上可以复制；点「重新输入」回登录页
- 有未保存的修改时退出或离开先确认

### 管理后台 (Admin)
- 系统统计（admin 及以上）
- 用户列表，分页（admin 及以上可看；改配额 / 禁用 / 删除按钮仅超管可见，superadmin 行不显示禁用和删除）
- 邀请码管理（admin 及以上；状态分「已使用」「已过期」「可用」，已使用的不显示删除）
- 文件元数据查看，分页（admin 及以上，只有元数据，无下载入口）
- 系统设置（开放注册、新用户默认配额，配额为空或非整数时拒绝保存；admin 只读，仅超管可保存）；设置没加载成功时表单显示的是默认值而不是真实设置，此时提示并禁用保存，避免覆盖真实设置

## 环境配置

### 开发环境

Vite 开发服务器会将 `/api` 和 `/ws` 请求代理到后端（`http://127.0.0.1:8000`）。

配置位于 `vite.config.js`：

```js
server: {
  port: 3000,
  proxy: {
    '/api': {
      // 用 127.0.0.1：后端只监听 IPv4，localhost 可能先解析成 ::1 导致代理失败
      target: 'http://127.0.0.1:8000',
      // 保留浏览器的 Host（localhost:3000），与经 Nginx 部署时一致
      changeOrigin: false,
    },
    '/ws': {
      target: 'ws://127.0.0.1:8000',
      ws: true,
    },
  },
}
```

### 生产环境

生产环境由 frontend 容器（[Dockerfile.frontend](../deployment/docker/Dockerfile.frontend)）在镜像内执行 `npm ci && npm run build`，产物 `dist/` 由容器里的 Nginx 托管，并反代 `/api`、`/ws` 到 backend 容器。Nginx 规则以 [deployment/docker/nginx-common.conf](../deployment/docker/nginx-common.conf) 为准（HTTP 站点 `nginx-docker.conf`、HTTPS 站点 `nginx-https.conf` 都引用它），部署步骤见 [deployment/DEPLOYMENT.md](../deployment/DEPLOYMENT.md)。

> 自己写反代时必须设置 `X-Forwarded-For`，否则后端只能看到 127.0.0.1，所有用户会共用一个限流额度。

## API 请求流程

1. **请求拦截**：自动附加 JWT Token（读本标签页 user store 里的 token，不读 localStorage，避免多标签页串号）
2. **发起请求**：通过 Axios 发送到后端
3. **响应拦截**：
   - 401，或带响应头 `X-Auth-Error: disabled` 的 403（账号被禁用）：登出并跳转登录页（登录 / 注册接口本身、登录页、注册页与快速访问页除外）
   - 普通 403（权限不足）与其他错误：提取 `detail` 字段返回；422 校验错误的 `detail` 是数组，取各条 `msg` 并去掉 pydantic 自带的英文前缀 `Value error,`

快速访问的请求走 `quickRequest.js`：带快速访问凭证，401 只结束快速访问（`useQuickStore().handleLost()`），不影响登录状态。

其他标签页登录、登出或换账号会改写 localStorage 中的 token，本页监听 `storage` 事件后整页重载。启动时只有 401 / 403 才清掉 token，网络错误或 5xx 保留登录状态并在登录页提示「暂时无法连接服务器」。

## WebSocket 连接

- **URL 构建**：根据当前协议（http/https）自动选择 `ws://` 或 `wss://`
- **认证**：Token 通过子协议传递（`new WebSocket(url, ['clipsync.v1', 'bearer.<token>'])`），不放 URL，避免被 access log 记录
- **心跳**：每 30 秒发送一次 ping；发出后 10 秒内没收到任何消息，就认为连接已半断（休眠、切网络后浏览器可能还没察觉）并立即重建
- **重连**：指数退避（1s、2s、4s…，最长 30s），不限次数；网络恢复或页面回到前台时立即重试：已断开的直接重连，看起来仍连着的先发一次 ping 探测，没有回应就重建；重连只用本标签页内存里的 token
- **关闭码**：已连接后被踢下线（账号被禁用或删除）为 1008，停止重连并登出；握手被拒时浏览器只能看到 1006，此时调一次 `/api/auth/me` 确认会话，401 / 禁用 403 则登出、不再重连，其他情况继续重连
- **补拉**：各页面同时订阅 `open`，连接（重新）建立后重拉一次数据，断线期间的变更不会漏掉
- **广播范围**：后端发给该用户的全部连接，触发变更的终端自己也会收到
- **离线发送**：连接未打开时 `send` 直接返回 false，不排队（客户端只发心跳，积压没有意义）
- **快速访问页**：`utils/websocket.js` 导出 `WebSocketManager` 类，快速访问页另建实例 `quickWs`（`stores/quick.js`），用快速访问凭证连接，重连与心跳规则相同；1008 时提示访问码已失效，握手被拒时请求一次 `/api/access/items` 确认

## 状态管理

所有状态通过 Pinia stores 管理，主要包括：

- **用户状态**：token、用户信息、登录状态、配额（已用 + 上传中）、启动时的连接错误提示
- **云剪切板状态**：当前文本、版本号、访问码与过期时间、历史记录、历史面板是否打开、编辑框是否有未保存的修改
- **文本栏目状态**：文本列表（长文本只有开头）、每人上限、列表加载失败的原因、是否有未保存的修改
- **文件状态**：文件列表（含访问码）、列表加载失败的原因、上传进度、是否正在上传、各文件的下载进度
- **访问码状态**：按访问码分组的总览（后端原始数据）、用户名、加载失败的原因
- **快速访问状态**：快速访问凭证、属主用户名、访问码、到期时间、是否已失效（不随登出重置，与登录状态互不影响）
- **管理后台状态**：统计数据、用户列表与分页、邀请码列表、文件元数据列表与分页、系统设置

登出时会清理各 store 的 WebSocket 监听并重置状态，下一个登录的账号看不到上一个账号的数据。

## 路由守卫

- **页面文件加载失败**：各页面按需加载。服务器升级后，已打开的旧页面里记的文件名在服务器上已不存在，点菜单会加载失败；`router.onError` 遇到这类错误会整页刷新一次拿到新版本，10 秒内已刷新过则不再刷，避免服务器真的连不上时陷入刷新循环
- **未登录**：自动跳转到 `/login`
- **已登录访问登录页**：跳转到 `/clipboard`
- **快速访问页 `/quick`**：不需要登录；没有快速访问凭证时页面自己回到 `/login`
- **非管理员访问管理后台**：跳转到 `/clipboard`

## 样式规范

设计变量与共用组件样式都在 `src/style.css`。页面只引用变量（`var(--color-text)` 等）和共用类（`.btn`、`.input`、`.table`、`.modal`……），不写死颜色值；页面自己的 `<style scoped>` 只放该页特有的布局。

- **颜色**：浅色主题，白底、浅灰分层，中性色为主
  - 主按钮用近黑色（`--color-primary`）；强调色靛蓝（`--color-accent`）只用于链接、焦点框、进度条、开关
  - 状态色：成功 / 警示 / 危险各有正文色与浅底色（`--color-success`、`--color-success-subtle` 等）
  - 文字与状态色在白底上满足 4.5:1 对比度
- **字体**：Inter（`@fontsource-variable/inter` 随前端打包，内网部署也能用，只含拉丁字符）；中文回落到系统字体（苹方、微软雅黑等）；代码与访问码用等宽字体（`.mono`）
- **字号**：12 / 13 / 14（正文）/ 15 / 17 / 20 / 24（页面标题）/ 32 / 40px
- **间距**：以 4px 为单位（`--space-1` 至 `--space-16`）
- **圆角**：6 / 8 / 12px；**阴影**：很轻的 `--shadow-xs` / `--shadow-sm`，弹窗用 `--shadow-lg`
- **图标**：`@lucide/vue` 细线图标，`App.vue` 统一设默认 16px、线宽 1.75；不用 emoji
- **提示与确认**：不用浏览器原生 `alert` / `confirm` / `prompt`；操作结果用 `toast`（`utils/toast.js`），确认与输入用 `confirmDialog` / `promptDialog`，多选一（如保存冲突）用 `choiceDialog`（`utils/dialog.js`）；复制失败时用 `copyDialog` 显示内容让用户手动复制。危险操作的确认框默认聚焦「取消」
- **窄屏**：768px 以下侧栏收起为抽屉（顶栏菜单按钮打开），表格可横向滚动；900px 以下登录 / 注册页隐藏左侧品牌介绍
- **动效**：150ms 颜色过渡；系统开启「减少动态效果」时关闭动画

## 注意事项

1. **协议无关**：前端使用相对路径和动态协议选择，同时支持 HTTP 和 HTTPS
2. **Token 管理**：Token 存在 `localStorage`（刷新后恢复登录、跨标签页感知），请求与 WebSocket 使用本标签页 store 中的副本，分别经 `Authorization` header 与子协议传递
3. **文件上传**：采用分片上传（1MB/片），支持大文件
4. **WebSocket 事件**（只带信号，不含正文）：
   - `clipboard_updated`：保存（含快速访问修改）、恢复或删除历史后触发；云剪切板页静默重拉当前文本，历史面板打开时一并重拉历史
   - `texts_changed`：新建、保存（含快速访问修改）、删除文本后触发；文本页静默重拉列表，访问码页重拉总览
   - `file_added` / `file_deleted`：文件页静默重拉列表；访问码页在 `file_deleted` 时重拉总览；侧栏配额由 `Home.vue` 统一刷新（连接重新建立 `open` 时也刷新一次）
   - `access_codes_changed`：设置、修改、清除访问码，或删除带访问码的文本 / 文件后触发；访问码页重拉总览，云剪切板、文本、文件页重拉以显示最新访问码
   - `access_items_changed`：只发给快速访问页，访问码下的内容有变化时触发，快速访问页静默重拉
   - `quota_updated`：超管修改配额后触发，侧栏刷新配额
5. **云剪切板历史**：点击条目把内容填入编辑框（不保存）；「恢复」按钮直接设为当前文本并同步；「删除」按钮删除该条历史
6. **权限控制**：前端隐藏只是体验层，后端必须做最终校验
